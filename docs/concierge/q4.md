### Q: With load_dotenv() and its default settings, if FOO=env is already set in the environment and my .env file has FOO=file and BAR=${FOO}, what value does BAR get?

BAR gets "env". With load_dotenv() the default is override=False, so resolve_variables lets os.environ take precedence over earlier .env values when expanding ${FOO}. FOO itself stays "env" in os.environ because it isn't overridden. If you pass override=True, FOO becomes "file" and BAR becomes "file".

```python
import os, tempfile
from dotenv import load_dotenv

os.environ["FOO"] = "env"
with tempfile.NamedTemporaryFile("w", suffix=".env", delete=False) as f:
    f.write("FOO=file\nBAR=${FOO}\n")

load_dotenv(f.name)  # override=False by default
print(os.environ["FOO"], os.environ["BAR"])  # env env

load_dotenv(f.name, override=True)
print(os.environ["FOO"], os.environ["BAR"])  # file file
```
